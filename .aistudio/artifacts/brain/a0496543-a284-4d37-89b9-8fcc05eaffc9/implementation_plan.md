# خطة العمل الهندسية: نظام طابور التنبيهات التسلسلي، إصلاح تطابق ملفات التحديث، واستعادة خيارات التنبيه السريع

معمارية شاملة لحل مشاكل التحديثات والتنبيهات في تطبيق «أثر» وفق الشروط والقرارات المؤكدة.

---

## User Review & Critical Decisions

> [!IMPORTANT] القرارات التي تم تأكيدها واعتمادها:
> - **طابور التنبيهات التسلسلي (Queue System)**: عند وصول تنبيه جديد أثناء عمل تنبيه حالي، لا تتم مقاطعة التنبيه أو فصل صوته إطلاقاً؛ بل يتم وضعه في طابور انتظار، وتحديث الشارة في الواجهة العائمة لإظهار عدد التنبيهات في الطابور (مثال: `تنبيه 1 من 3 · +2 في الانتظار`). فور انتهاء الصوت الحالي تلقائياً (`STATE_ENDED`) أو ضغط المستخدم على إغلاق، ينتقل النظام تلقائياً للتنبيه التالي في الطابور بالدور.
> - **إلغاء التراكم عند فتح التطبيق (Zero Backlog on App Launch)**: أي تنبيهات مضى وقتها أثناء إغلاق التطبيق تسقط تماماً ولا تُرسل دفعة واحدة. يُعاد تصفير وتعيين عدادات التنبيهات الأربعة لحظة فتح التطبيق ليبدأ العد للفترة الكاملة التي حددها المستخدم بدءاً من لحظة الفتح.
> - **فحص التحديث برقم الإصدار الحقيقي (Strict Version Matching)**: ربط التحقق من ملف التحديث برقم الإصدار الفعلي المستهدف (مثال: `athar-v1.0.327.apk`) وإلغاء الاسترداد العشوائي لأي ملف APK قديم في ذاكرة التخزين المؤقت، مع مسح ملفات التحديثات القديمة تلقائياً.
> - **استعادة خيارات التنبيه السريع (5 ثوانٍ ودقيقة)**: إعادة إضافة الخيارات السريعة (`5s` و `1m`) في القوائم المنسدلة للتنبيهات الأربعة لتسهيل التجربة والفحص الفوري.

                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│              AtharFloatingWindowService (Strict Queue)                 │
│                                                                        │
│   Is audio playing or window actively displayed?                       │
│   ├── YES ──► Enqueue into alertQueue (FIFO)                           │
│   │           Update Queue Badge on current UI (e.g. "+1 في الانتظار") │

│   │                                                                    │

│                                                                        │

│   ├── If queue has next ──► Smoothly In-Place Update to Next Alert     │

│   └── If queue empty    ──► Cleanly dismiss overlay and stop           │

│                  App Launch Reminder Initialization                    │
│                                                                        │
│   When app opens:                                                      │
│   - Reset all 4 reminder timestamps to Date.now()                      │
│   - Do NOT fire any overdue backlog alerts                             │
│   - Next alert fires only after user's configured interval (e.g. 1h)   │

## 2. Detailed Implementation Phases

### 2.1 إصلاح تطابق ملف التحديث وفصل الإصدار القديم عن الجديد
1. **في `NativePermissionsPlugin.kt`**:
   - تعديل `checkDownloadedApk`: إزالة المنطق القديم الذي يبحث عن "أحدث APK في المجلد بغض النظر عن الاسم".
   - التحقق الصارم من أن الملف المطلوب `fileName` (المحتوي على رقم الإصدار مثل `Athar-v1.0.327.apk`) موجود بالفعل وحجمه مطابق.
   - إضافة دالة لتنظيف أي ملفات APK سابقة للإصدارات القديمة في مجلد `cacheDir/updates`.
2. **في `appUpdateService.ts`**:
   - إزالة الفحص العام غير المشروط من `localStorage` مثل `athar_cached_apk_downloaded` العام.
   - جعل مفتاح التخزين مرتبطاً حصرياً برقم الإصدار: `athar_downloaded_${updateInfo.latestVersion}`.
   - ضمان ظهور زر "تنزيل وتثبيت التحديث الآن" بشريط التقدم الحقيقي عند عدم وجود الملف الجديد، وعدم إظهار "الملف جاهز" إلا إذا كان الملف الموجود هو فعلياً الإصدار الجديد المستهدف.

### 2.2 استعادة خيارات التنبيه السريع (5 ثوانٍ ودقيقة)
1. **في `RoyalRemindersMasterCard.tsx`**:
   - إضافة خياري:
     - `{ value: '5s', label: 'كل ٥ ثوانٍ (تجربة سريعة)' }`
     - `{ value: '1m', label: 'كل دقيقة (تجربة)' }`
     إلى مصفوفة `freqOptions` لجميع التنبيهات الأربعة (الآية، الأذكار، الورد، بر الوالدين).
2. **في `reminderService.ts`**:
   - التأكد من أن دالة `parseFrequencyMs` تدعم `5s` (5000 مللي ثانية) و `1m` (60000 مللي ثانية).

### 2.3 بناء نظام طابور التنبيهات (Queue System) في النافذة العائمة
1. **طابور تسلسلي محمي (`ArrayDeque<FloatingAlertData>`)**:
   - عند استقبال تنبيه جديد في `AtharFloatingWindowService`:
     - إذا كانت النافذة معروضة وهناك صوت شغال أو بطاقة نشطة: **يُمنع مقاطعة التنبيه الحالي نهائياً**، ويُضاف التنبيه الجديد إلى نهاية الطابور `alertQueue.offer(alertItem)`.
     - يتم تحديث شارة الطابور على الكارت المعروض حالياً لإعلام المستخدم (مثال: `الشارة الحالية · (+1 في الانتظار)`).
   - عند انتهاء صوت التنبيه الحالي (`STATE_ENDED`) أو ضغط المستخدم على إغلاق:
     - التحقق مما إذا كان هناك تنبيهات في الطابور `if (alertQueue.isNotEmpty())`.
     - سحب التنبيه التالي `alertQueue.poll()`.
     - تحديث الواجهة فورياً بنفس الـ View (In-Place Update) مع تصفير شريط التقدم وتشغيل الصوت الخاص بالتنبيه الجديد تلقائياً.
     - إذا كان الطابور فارغاً، يتم إغلاق النافذة العائمة وتفريغ المشغل فوراً.

### 2.4 حل مشكلة التنبيهات المخزنة عند فتح التطبيق (Zero Backlog)
1. **في `reminderService.ts` عند بدء تشغيل المحرك (`start()`)**:
   - تعيين كافة التواريخ الأخيرة `athar_last_ayah_reminder_ts` وغيرها إلى `Date.now()`.
   - عدم إطلاق أي تنبيه متأخر مر وقته أثناء إغلاق الهاتف أو التطبيق.
   - يبدأ العد التنازلي للفترة المحددة (مثلاً بعد ساعة أو بعد 5 ثوانٍ إذا اختار المستخدم ذلك) بدءاً من لحظة فتح التطبيق الحالية.
   - منع تشغيل أي استدعاءات متزامنة للتنبيهات الأربعة عند التشغيل.
