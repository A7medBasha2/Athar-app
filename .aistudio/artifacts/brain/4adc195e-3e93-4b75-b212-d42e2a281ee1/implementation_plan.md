# خطة بناء نظام التحديثات الداخلي (In-App Update System) عبر GitHub Releases

تهدف هذه الخطة إلى بناء وتفعيل نظام تحديثات داخلي ذكي، احترافي، ومتكامل تماماً لتطبيق «أَثَرُ» على منصة أندرويد وCapacitor، متصل مباشرة بـ **GitHub Releases** للتحقق من الإصدارات الجديدة، وإظهار بطاقة عائمة ملكية راقية، وتنزيل ملف التحديث (APK) مع شريط تقدم حي، ثم إطلاق عملية التثبيت الفوري بسلاسة، مع الحفاظ التام والمطلق على كافة بيانات وقواعد بيانات وإعدادات المستخدم المحلية.

---

> [!IMPORTANT]
> **القرارات المؤكدة المعتمدة (Decisions Confirmed):**
> 1. **مستودع GitHub المعتمد:** الربط البرمجي بمستودع أثر الرسمي المباشر (`tophdesigns2016/athar` مع إمكانية التعديل والتخصيص وحفظه بأمان).
> 2. **آلية التنزيل والتثبيت:** تنزيل ملف الـ APK المباشر من أصول الإصدار (Release Assets) مع شريط تقدم بالنسبة المئوية وحجم الملف، ثم التثبيت الفوري عبر Android Package Installer.
> 3. **طريقة الإشعار:** بطاقة عائمة ملكية فاخرة (Royal Floating Card) بتصميم متناسق مع هوية التطبيق، تحتوي على رقم الإصدار الجديد، وسجل التغييرات (Changelog)، وزر للتحديث الفوري، وزر لتأجيل الإشعار لهذه الجلسة فقط دون ظهوره مجدداً حتى إعادة تشغيل التطبيق.
> 4. **الفحص اليدوي:** إضافة خيار مخصص وأنيق داخل شاشة الإعدادات للتحقق اليدوي في أي وقت مع عرض حالة الإصدار الحالي فوراً.

## 2. المكونات البرمجية المطلوب إنشاؤها وتحديثها (Components & Services)

### أولاً: طبقة الخدمات البرمجية (Core Services)
1. **`src/services/appUpdateService.ts`**:
   - الاتصال بـ GitHub Releases API وجلب تفاصيل أحدث إصدار (`tag_name`, `body`, `assets`, `published_at`).
   - خوارزمية ذكية لمقارنة أرقام الإصدارات الدلالية (`compareVersions(current, latest)`).
   - إدارة حالة الجلسة وتأجيل التنبيه (`sessionDismissedFlag`).
   - استخراج رابط الـ APK المباشر من الـ Assets (البحث عن `*.apk`).
   - حساب وتتبع تقدم التنزيل الفعلي (Bytes Received / Total Bytes / Percentage).
   - إطلاق تثبيت الـ APK عبر الجسر الأصلي (Native Bridge) أو روابط الحزمة.

2. **`src/services/nativePermissionsBridge.ts`**:
   - إضافة دوال جسر أندرويد الأصلية الخاصة بالتحديثات:
     - `installApk(filePathOrUrl)`
     - `canRequestPackageInstalls()`
     - `openInstallUnknownAppsSettings()`

### ثانياً: طبقة أندرويد الأصلية (Native Android Layer)
1. **تحديث `AndroidManifest.xml`**:
   - إضافة إذن طلب تثبيت الحزم: `<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES" />`.
   - توفير `FileProvider` رسمي (`androidx.core.content.FileProvider`) داخل التطبيق لتمكين تثبيت ملفات الـ APK المنزلة بأمان مع منح أذونات القراءة المؤقتة لمثبت حزم النظام `FLAG_GRANT_READ_URI_PERMISSION`.
2. **إنشاء ملف إعدادات المسارات `android/app/src/main/res/xml/file_paths.xml`**:
   - دعم مسارات `cache-path` و`external-cache-path` و`files-path`.
3. **تحديث `NativePermissionsPlugin.kt` / `MainActivity.java`**:
   - إضافة دالة `downloadAndInstallApk` باستخدام `DownloadManager` أو تنزيل تدفقي، وتشغيل `Intent.ACTION_VIEW` مع MIME Type `application/vnd.android.package-archive`.

### ثالثاً: واجهة المستخدم الملكية (UI & Components)
1. **`src/components/AppUpdateModal.tsx`**:
   - بطاقة عائمة فاخرة ذات طابع أندلسي ملكي (Royal Dark Gold Theme).
   - تفاصيل الإصدار الجديد (الإصدار الحالي -> الإصدار الجديد).
   - عرض سجل التغييرات ومميزات التحديث بصيغة منسقة وأنيقة.
   - شريط تقدم تفاعلي (ProgressBar) بنسبة مئوية ومؤشر السرعة/الحجم.
   - أزرار «تحديث وتثبيت الآن» و«تذكيري في الجلسة القادمة».
2. **دمج المكون في `App.tsx`**:
   - تفعيل فحص التحديث التلقائي الصامت فور انتهاء تهيئة التطبيق.
   - عدم تكرار ظهور النافذة إذا ضغط المستخدم على تأجيل إلا عند إعادة فتح التطبيق بالكامل.
3. **تحديث شاشة الإعدادات `src/views/SettingsView.tsx`**:
   - إضافة بطاقة مخصصة في قسم إعدادات التطبيق: «التحقق من التحديثات»، تعرض رقم الإصدار الحالي (`v1.0.195` / `1.0.0`)، وزر «بحث يدوي عن تحديث» مع دوران أيقونة التحميل وحالة الاستجابة اللحظية.

## 4. قائمة التحقق وضمان جودة البيانات (Verification Checklist)

- [x] **سلامة بيانات المستخدم:** عمليات التحديث لن تلمس إطلاقاً `localStorage` أو `IndexedDB` أو إعدادات التطبيق المحفوظة.
- [x] **انضباط الجلسة:** عند إغلاق التنبيه، يتم احترام رغبة المستخدم وعدم إزعاجه مرة أخرى طوال فترة عمل الجلسة الحالية.
- [x] **دعم العمل دون اتصال:** في حال انقطاع الإنترنت أو بطء GitHub API، يفشل الفحص بصمت دون أي تأثير سلبي على سرعة تشغيل التطبيق.
- [x] **أفضل الممارسات البرمجية:** كود نظيف، مكتمل بالكامل، يدعم TypeScript الصارم، ومتوافق مع أحدث مواصفات أندرويد وCapacitor.
